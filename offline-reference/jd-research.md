## Reusable accelerators need contracts and maintenance

A migration preview has a concrete review boundary: OpenRewrite's Maven dryRun produces a patch without applying source edits; run applies changes. A preview is not behavioral parity, so the lesson adds accepted input versions, allowed roots, owner, diff review, build/tests and rollback evidence. Packaging a prompt alone does not establish repeatable adoption. A useful first accelerator can provide inventory and supported recipe previews before acquiring broader write authority. These product-design recommendations follow the JD's reusable-engineering requirement, not a source claim that every team should use the same topology. ## MCP protocol knowledge must be revision-specific

The official latest specification currently resolves to 2026-07-28. Its core describes self-contained requests with per-request version and capability metadata. Earlier 2025-11-25 implementations use the initialize lifecycle. Therefore an answer that states “every MCP connection begins with initialize” as a universal current rule is incomplete. Pin the protocol and independently record client, SDK and server versions; verify supported combinations rather than deriving compatibility from a library label. [Current specification](https://modelcontextprotocol.io/specification/2026-07-28), [current transport overview](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [legacy lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

stdio carries newline-delimited protocol messages and reserves stdout for those messages; logs belong on stderr. Current Streamable HTTP uses request delivery with JSON or request-scoped streaming responses. It requires Origin validation and recommends restricted local binding and appropriate authentication. Streaming or canceled delivery is not durable state or proof of downstream rollback. [stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http).

Tools expose invocable contracts; resources expose context. Consumers must validate structured results and distinguish tool execution errors from protocol errors. A result can carry isError, so HTTP success alone is not application success. The lesson's compatibility matrix is proposed evidence, not a executed MCP server. Spring AI supports MCP integrations, but its documentation also contains transport package/dependency changes across major versions; starter availability is not a universal protocol-conformance claim. [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [Spring AI MCP overview](https://docs.spring.io/spring-ai/reference/api/mcp/mcp-overview.html).

## MCP security continues at the application boundary

For protected HTTP integrations, validate access tokens for the MCP resource audience and use the documented resource-server flow. The security guidance forbids accepting an unrelated token and blindly forwarding it downstream. Operation-level policy still decides repository roots, tenant access and permitted effects. Authenticated HTTP access does not authorize arbitrary shell execution. Treat annotations as descriptions rather than enforcement, separate preview/apply, bind review to exact intent and recheck current authority. stdio process credentials require an explicit local launch policy rather than importing the HTTP OAuth flow. [Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [security practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices).

The proposed assignment traces a Spring controller through service policy to a tenant-scoped repository, then a Python analysis contract and a TypeScript status interface. ## Evaluation and observability answer different questions

Use representative and held-out tasks, declared acceptance gates, adversarial cases and failure categorization. Model grading needs calibration and cannot grant permission. Trace stages connect recorded operations and timing; they do not certify factuality or authorization. Collect sanitized identifiers, outcome categories, versions, attempts, latency and documented usage. Compute cost per accepted task using explicit assumptions, including retries/review, rather than inventing current API rates. Local OpenAI SDK inspection in the earlier research found no installed SDK, so official documentation was the fallback; no API calls or provider benchmarks were made. [Evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices), [OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/), [token counting](https://developers.openai.com/api/docs/guides/token-counting).

## Cloud operation requires tested identity and failure paths

AWS recommends temporary workload credentials through roles and least privilege. Separate human, CI and runtime identity. Kubernetes probes have different readiness, liveness and startup roles; NetworkPolicy only takes effect with an enforcing networking implementation. The lesson asks for one concrete cloud path, tested connection rules, graceful termination, durable task recovery and bounded retry/restoration decisions. It does not provision cloud resources or claim regional service interchangeability. [AWS IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html), [probes](https://kubernetes.io/docs/concepts/workloads/pods/probes/), [NetworkPolicy](https://kubernetes.io/docs/concepts/services-networking/network-policies/), [bounded retries](https://docs.aws.amazon.com/wellarchitected/2024-06-27/framework/rel_mitigate_interaction_failure_limit_retries.html).

## Secure SDLC and adoption are leadership responsibilities

NIST SSDF frames lifecycle responsibilities. SLSA provenance provides artifact build/origin evidence; an SBOM inventories components, and neither guarantees vulnerability absence. GitHub warns against privileged workflows checking out untrusted PR code and recommends least privilege and immutable action references. License review remains an explicit owner decision, not an AI legal conclusion. The JD specifically requires human review before production release. [NIST SSDF](https://csrc.nist.gov/pubs/sp/800/218/final), [SLSA provenance](https://slsa.dev/spec/v1.2/provenance), [CI secure use](https://docs.github.com/en/actions/reference/security/secure-use), [dependency inventory](https://docs.github.com/en/code-security/concepts/supply-chain-security/dependency-graph).

Current DORA guidance covers five delivery metrics spanning throughput and instability. Use a baseline, matched task/cohort context and explicit expand/revise/stop rules; usage counts are insufficient evidence of business improvement. Quality, reviewer effort, cost and developer experience belong alongside delivery results. Before/after observations require caution about confounding and cannot guarantee AI caused an improvement. Leadership preparation should distinguish owned experience from a proposed pilot and state the evidence that would change a decision. [DORA delivery metrics](https://dora.dev/guides/dora-metrics/).
