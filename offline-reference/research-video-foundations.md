# Verified foundation and implementation videos

Verified on **2026-10-09**. This memo supports `video-foundations.json`, containing 25 exact YouTube watch URLs. Verification means the resource identity and advertised subject were checked through first-party creator/publisher pages or indexed YouTube metadata. It does **not** mean the video was played, every line of sample code was executed, captions were audited, the whole course was quality-certified, or availability was confirmed in every region. Some direct YouTube page fetches exposed only a footer; publisher links or indexed first-party metadata supplied the usable identity evidence.

The choices are curriculum recommendations, not predictions of a particular employer's questions or a guarantee of passing an interview. The learner's implementation receipt, ability to explain a tradeoff and ability to diagnose a failure establish preparation evidence. Watching a course establishes exposure.

## Selection and use

Use a focused explanation to repair a conceptual gap, then produce the card's practice artifact before marking it complete. Long courses are reference libraries: select the listed subject sections instead of allocating the complete course to one day. The tutorial assignments and day links are our teaching recommendations; the sources establish video identity and subject, not our proposed schedule. They must fit inside the learner's chosen daily study allocation or be explicitly optional additional work.

The foundation route is Python objects → concurrency → HTTP/schema contracts → statistical reasoning → model evaluation → tensor/training workflow → transformer/tokenizer explanation. Framework videos then make the concepts concrete. RAG, agent, cloud identity, modernization and leadership resources support a principal-level defense of the resulting implementation.

The updated Django choice is a focused 2025 crash course instead of an unresolved broad-course mapping. Java uses the currently indexed title “Java Full Course for Beginners,” although older copies may call the same ID a tutorial. Provider- and framework-sensitive examples need current documentation before execution. No historical service price, “free tier,” benchmark superiority or current model ranking is copied into the curriculum.

## Boundaries that matter during interview preparation

**Statistical validation:** The cross-validation video is a foundation for comparison. The curriculum assignment deliberately adds entity grouping because repeated users, claims or documents can leak information across folds. Time-dependent data may require a temporal split instead. Preprocessing must fit only on training records, and final test data must remain independent of model selection. The Bayes task's defect counts are invented teaching data and must never be described as production evidence. [Cross-validation lesson](https://www.youtube.com/watch?v=fSytzGwwBVw), [Bayes lesson](https://www.youtube.com/watch?v=9wCnvr7Xw4E).

**Implementation libraries:** The creator's PyTorch course explicitly separates tensor foundations and the training workflow. Its linked runnable notebooks are a useful optional real-library path. An offline stdlib derivative toy remains a toy; it cannot be reported as a PyTorch experiment. The Flask and FastAPI recordings are older. A tutorial's old framework, ORM or cloud deployment instructions must be checked against the learner's installed versions. [PyTorch publisher and syllabus](https://www.freecodecamp.org/news/learn-pytorch-for-deep-learning-in-day), [FastAPI publisher](https://www.freecodecamp.org/news/creating-apis-with-python-free-19-hour-course/), [Flask publisher](https://www.freecodecamp.org/news/learn-flask-for-python-full-tutorial).

**Language-model components:** Karpathy's creator repository describes tokenization as a distinct stage with encode/decode functions and its own training algorithm. The decoder-model and tokenizer lessons should therefore produce two distinct teach-backs. Character counts, byte counts and a local toy BPE vocabulary do not establish a provider request's token usage. Current model/request framing is a separate integration contract. [Creator course repository](https://github.com/karpathy/nn-zero-to-hero).

**RAG and measurement:** Lance Martin's video metadata lists indexing, retrieval, generation, query translation and routing. The learning task isolates these stages rather than attributing every miss to a model. DeepLearningAI's evaluation workshop explicitly discusses RAG and supervised/model-assisted evaluation. The fixture's answer labels, unknown cases, scope violations and individual traces need inspection; a judge model's score is not an independent truth certificate. A lexical retriever is not an ANN implementation, and local fixture metrics are not a deployed provider's hallucination rate. [RAG course](https://www.youtube.com/watch?v=sVcwVQRHIc8), [Evaluation workshop](https://www.youtube.com/watch?v=7EcznH0-of8).

**MCP compatibility and authority:** The freeCodeCamp publisher explicitly advertises Python SDK server/client construction. This makes it a useful implementation resource, but its January 2026 release does not establish conformance to every later protocol revision. The learner should pin the implemented revision and capture initialization, capability discovery, successful invocation and rejected invalid requests. Remote OAuth, tenant authorization, prompt assets and tool permissions are separate controls and may need additional current protocol documentation. [Publisher course and exact video link](https://www.freecodecamp.org/news/learn-rag-and-mcp-fundamentals).

**Cloud identity:** AWS's own role guide and Savill's managed-identity deep dive support two concrete designs for machine identity. Identity proves a caller; a role assignment or permission policy authorizes specific actions. Designing those policies is valid interview practice, while a live account test is separate evidence. The shortlist imposes no cloud purchase or account requirement. [AWS role guide](https://www.youtube.com/watch?v=miij_0HkBws), [Azure managed identity](https://www.youtube.com/watch?v=rC1TV0_sIrM).

**Modernization:** The YouTube index for the Moderne example has a blank display-title field but provides the official channel and detailed demo description. The resource card uses the publisher page's descriptive demo label; it does not claim that blank metadata was an exact title. Its example transformation counts and estimated saved time are not evidence about this learner or an organization. An OSS recipe's dry run plus compile/behavior tests is a separate assignment, and hosted-platform access remains optional. [Publisher demo](https://www.moderne.ai/downloads/running-your-first-recipe-on-the-moderne-platform-video), [Official recipe-demo video](https://www.youtube.com/watch?v=2-msv8LBmYg), [Current introduction workshop](https://docs.moderne.io/hands-on-learning/introduction/workshop-overview/).

**Agents and adoption:** Anthropic's discussions supply a model-author perspective on workflow/agent choices and coding practices. The small controlled patch comparison and evaluation rubric are curriculum additions, not an assertion that watching a talk proves an accelerator's value. Similarly, Dave Farley's team-leadership principles inform a pilot plan; the video is not misrepresented as a measured AI-adoption study. Actual baseline, cycle-time, defect and developer-feedback observations must be gathered during a real pilot. [Agent discussion](https://www.youtube.com/watch?v=LP5OCa20Zpg), [Coding-agent conference session](https://www.youtube.com/watch?v=gv0WHhKelSE), [Companion engineering article](https://www.anthropic.com/engineering/claude-code-best-practices), [Technical-team leadership](https://www.youtube.com/watch?v=jMpCF0Z623s).
